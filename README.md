# Scripts Manager — руководство пользователя

Программа для запуска скриптов с формой параметров: T-SQL, PL/pgSQL, PowerShell и Python.
Замена Red Gate SQL Scripts Manager: даты с календарём, необязательные параметры, подпапки, несколько серверов и баз,
общие скрипты через git.

## Установка

**[Скачать последнюю версию](https://github.com/SubZenzo/scripts-manager/releases/latest/download/ScriptsManager.App.exe)**
— один файл `ScriptsManager.App.exe`, устанавливать .NET и что-то ещё не нужно. Положите его куда удобно и
запускайте. Все версии и что в них изменилось — в [релизах](https://github.com/SubZenzo/scripts-manager/releases).

Исходный код — в `src` ([для разработчика](src/README.md)).

Для отдельных возможностей нужны:
- **git** — общая папка скриптов в репозитории (получение и публикация изменений);
- **Python** — для скриптов `.py` (путь задаётся в настройках, по умолчанию `python` из PATH);
- **PowerShell 7** (`pwsh`) — только если хотите запускать `.ps1` им, а не встроенным Windows PowerShell 5.1.

Новая версия — скачайте по той же ссылке и замените exe (программу перед этим закройте). Версия видна в свойствах
файла (вкладка «Подробно»).

## Первый запуск: папки со скриптами

«Настройки» → «Папки со скриптами» → «Добавить…». Папок может быть несколько, например:
- командная — папка `scripts` этого репозитория;
- личная — любая своя папка.

Порядок папок в дереве меняется кнопками «Выше» / «Ниже». Там же — пути к Python и PowerShell.

## Главное окно

- **Слева** — дерево: папка со скриптами → подпапки → скрипты. Значок у скрипта — язык: значок Management Studio — T-SQL,
  слоник pgAdmin — PL/pgSQL, синяя плашка с `>_` — PowerShell, сине-жёлтый — Python. Над деревом поиск и плашки
  тегов (см. «Теги»).
  F5 — перечитать папки.
- **Под деревом** — список «Запуски» (появляется после первого запуска). 
- **Справа** — карточка выбранного скрипта: описание, форма параметров и вкладки «Скрипт», «Результат»,
  «Вывод» (для PowerShell и Python), «Описание» (если автор написал подробное описание).

Серым курсивом в дереве показаны файлы скриптов, для которых ещё нет описания параметров (манифеста). Запустить их
нельзя — сначала «Изменить…» (см. ниже).

## Теги

Теги — метки скрипта, по которым его удобно найти независимо от папки: например, `DBA`, `Kafka`,
`Utils`. У скрипта может быть несколько тегов.

**Поиск по тегам.** Над деревом — плашки всех тегов из всех папок со скриптами.
- Щелчок по плашке отмечает тег: в дереве остаются только скрипты с этим тегом.
- Несколько отмеченных тегов сужают список: остаются скрипты, у которых есть **все** отмеченные теги.
- × рядом с плашками снимает все отметки.
- Теги работают вместе с поиском. Поиск ищет и в названии, и в имени файла, и в тегах: `kafka` найдёт скрипты с
  тегом `Kafka`.

**Как задать теги.** В окне «Добавить скрипт…» / «Изменить…» теги показаны плашками:
- выберите тег из списка (там теги других скриптов) или введите новый и нажмите Enter;
- × на плашке убирает тег.

Большие и маленькие буквы не различаются: `kafka` и `Kafka` — один тег. Перед тем как заводить новый тег,
посмотрите в списке, нет ли уже подходящего — иначе появятся почти одинаковые теги, и фильтр по ним разойдётся.
Теги хранятся в манифесте скрипта (`tags: [DBA, Kafka]`) и публикуются вместе с ним, поэтому общие для всей
команды.

## Запуск скрипта

1. Выберите скрипт в дереве.
2. Выберите подключение: поле сервера с недавними подключениями, кнопка «…» открывает окно подключения
   (сервер, способ входа, пароль, база). У скрипта может быть несколько подключений — у каждого своё поле.
   Последний выбор запоминается для скрипта.
3. Заполните параметры. Обязательные помечены; пустой необязательный параметр передаётся в скрипт как `NULL`.
4. «Запустить». Если скрипт что-то меняет, его автор мог включить подтверждение — будет окно с сервером и
   значениями.

«Остановить» прерывает запрос или завершает процесс скрипта.

### Поля параметров

| Поле | Как заполнять |
|---|---|
| Строка, текст | как есть; текст — многострочный |
| Число | цифры; автор скрипта может ограничить диапазон |
| Флажок | да / нет |
| Дата, дата и время | календарь или вручную |
| GUID | проверяется формат |
| Список | выбор из выпадающего списка; если список редактируемый — можно ввести своё значение |
| Несколько значений | выпадающий список с флажками и поиском; «все» / «ничего» действуют на найденные |
| Номера и диапазоны | `1, 5, 2..4, 6..10` — через запятую или каждый с новой строки; порядок сохраняется, `10..6` — по убыванию. Под полем видно, сколько номеров получилось и какие повторяются |
| Папка, файл | кнопка выбора |

«Сбросить» возвращает значения по умолчанию.

### Пресеты

Пресет — сохранённый набор значений формы вместе с подключениями (например, «Роуминг», «Неделя»).
- Выбор пресета подставляет его значения поверх значений по умолчанию.
- «Сохранить как…» — сохранить текущие значения (то же имя — заменить), «Удалить» — удалить пресет.
- Пока пресет не опубликован (см. «Общие скрипты»), он есть только у вас.

## Результаты

На вкладке «Результат» — лог (сообщения `PRINT`, `RAISE NOTICE`, вывод скрипта, ошибки) и таблицы: каждый
набор результатов — отдельная вкладка с числом строк. В заголовке видно, где и когда был запуск, и сколько он шёл.

Работа с таблицами:
- щелчок по заголовку строки или столбца выделяет его (Ctrl — добавить, Shift — диапазон);
- правый щелчок по заголовку столбца — сортировка (если строк не больше 5000);
- Ctrl+C — копировать выделенное, Ctrl+Shift+C — с заголовками (вставляется в Excel);
- «Сохранить…» — в Excel (xlsx) или CSV;
- «Копировать как ▾» — выделенное (или всю таблицу) в разметке Jira / Confluence, Markdown или как
  `select … from (values …)` для SQL Server / PostgreSQL; «Показать текстом…» — то же в окне;
- «Сохранить значение как…» (контекстное меню, выделена одна ячейка) — значение в файл: текст в UTF-8, бинарные
  данные — как есть (например, план запроса — в `.sqlplan`, архив — в `.zip`). Бинарные значения длиннее 1024 байт
  программа целиком не хранит (в таблице — начало и размер), для них пункт недоступен — выгрузите их другим способом.

Даты показываются как `2026-11-20 14:05:00`, большие числа — с пробелами между разрядами. При копировании и
сохранении берутся исходные значения.

## Несколько запусков и оповещения

- Можно запускать сразу несколько скриптов и один и тот же скрипт несколько раз — например, на разных серверах.
  «Запустить» доступна и во время выполнения.
- Список «Запуски» показывает все запуски за сеанс, новые сверху: значок состояния (стрелки — выполняется,
  галочка — выполнено, крестик — ошибка, квадрат — остановлено), название, время, подключение, длительность.
  Непросмотренные результаты — жирным.
- Щелчок по запуску открывает его результат. Правый щелчок: «Открыть результат», «Переименовать…» (своё название,
  например имя сервера, — чтобы отличать результаты), «Удалить результат». «Убрать завершённые» очищает список.
- Если у скрипта несколько запусков, на вкладке «Результат» есть выбор запуска.
- Если автор скрипта включил повторный запуск, на вкладке «Результат» есть кнопка со значком обновления —
  «Запустить ещё раз»: новый запуск с теми же параметрами и подключением, что у выбранного запуска. Прежний
  результат остаётся в списке.
- Когда запуск завершается, а его результат не на экране, в правом нижнем углу окна появляется сообщение с кнопкой
  «Открыть». Если окно свёрнуто или неактивно, ещё мигает кнопка на панели задач и всплывает уведомление Windows;
  щелчок по нему открывает результат.

## Вывод скриптов PowerShell и Python

У каждого такого скрипта есть постоянная папка вывода `.output\<путь скрипта>` в папке со скриптами — туда скрипт
пишет логи и другие файлы (путь он получает в `OUTPUT_DIR`). Вкладка «Вывод» показывает файлы этой папки (новые
сверху) и содержимое выбранного; есть «Обновить», «Открыть папку», «Открыть файл» (или двойной щелчок), «Удалить».
Эти файлы не публикуются в git.

## Добавление и правка скриптов

«Добавить скрипт…» (кнопка, меню папки в дереве или перетащите файл в окно) и «Изменить…» (меню скрипта, кнопка в
карточке) открывают окно правки:
- скрипт — из файла (`.sql`, `.ps1`, `.py`) или вставкой текста; язык определяется сам;
- название, описание, теги, подтверждение перед запуском, повторный запуск (кнопка «Запустить ещё раз» на вкладке
  «Результат»; по умолчанию выключен), вид вывода; для нового — папка и имя файла;
- подробное описание в markdown (вкладка «Описание»): заголовки, списки, таблицы, код,
  ссылки. Пользователь видит его на вкладке «Описание» карточки скрипта;
- **параметры программа находит в тексте сама**: `DECLARE` в начале T-SQL, `param()` в PowerShell, `add_argument`
  в Python, `@имя` в PL/pgSQL. Снимите отметку «сделать параметром», если переменная должна остаться внутри скрипта;
- у параметра можно поменять подпись, подсказку, тип, обязательность, значение по умолчанию, диапазон, элементы
  списка; параметры можно добавлять, удалять и переставлять. Значение по умолчанию для дат — `now`, `today`,
  `today-7`, `now-1h`;
- подключения: имя, СУБД, «только сервер» (без выбора базы).

При сохранении программа приводит скрипт в соответствие с параметрами:
- T-SQL — объявления параметров собираются в блок `--#region Params` … `--#endregion`, поэтому скрипт можно
  запускать и в SSMS; при запуске из программы этот блок не выполняется, значения берутся из формы;
- PowerShell и Python — параметры, добавленные вручную, объявляются в скрипте (`param()` / `add_argument`).

«Удалить…» (меню скрипта, кнопка в карточке) отправляет скрипт, его манифест и пресеты в корзину Windows.
Папка вывода остаётся.

## Общие скрипты (git)

Если папка со скриптами — git-репозиторий:
- программа при старте проверяет, есть ли изменения на сервере; «Получить изменения с сервера (git pull)» забирает их;
- изменённые и новые скрипты отмечены в дереве;
- «Опубликовать…» — выбрать скрипты и пресеты, написать сообщение, программа сделает commit и push в текущую ветку.
  Скрипт публикуется вместе с манифестом, пресеты — по одному (по умолчанию не отмечены);
- «Копировать в» — скопировать скрипт с манифестом и пресетами в другую папку (например, из личной в командную).

Конфликты и ветки — в обычном git.

## Как писать скрипты

Значения параметров подставляются автоматически — в скрипте их не нужно объявлять (кроме PowerShell и Python, где
это сделает окно правки).

**T-SQL.** Параметры — `@имя`. `GO` поддерживается. Несколько значений из списка — JSON-строка:
`select value from openjson(@stands)`. Номера и диапазоны — тоже JSON: `select cast(value as int) from openjson(@servers)`.

**PL/pgSQL.** В обычных запросах — `@имя`. Внутри `DO $$ … $$` параметры — переменные `declare`: окно правки
находит их (`l_from date := current_date - 1` → параметр `l_from`, «сегодня − 1 день»; имя — как у переменной) и при сохранении подставляет
значение из приложения: `l_from date := nullif(coalesce(current_setting('param.l_from', true), (current_date - 1)::text), '')::date`.
Вне приложения действует прежнее значение. Добавленные вручную параметры дописываются в `declare` под своим именем.
Несколько значений — `json_array_elements_text(@имя::json)`.

**PowerShell.** Параметры — блок `param()`: флажок — `[switch]` или `[bool]`, несколько значений — `[string[]]`,
номера — `[int[]]`. Подключения — переменные окружения: `$env:DB_<ИМЯ>_CONNSTR` (строка подключения), а также
`DB_<ИМЯ>_SERVER`, `_DATABASE`, `_USER`, `_PASSWORD`. Папка вывода — `$env:OUTPUT_DIR`. Сохраняйте `.ps1`
в **UTF-8 с BOM**, иначе Windows PowerShell испортит кириллицу; логи пишите с `-Encoding UTF8`.

**Python.** Параметры — `argparse` (`--имя`); подключения — те же переменные окружения и `DB_<ИМЯ>_ODBC` для pyodbc,
для PostgreSQL ещё `PGHOST`, `PGDATABASE` и т.д. Папка вывода — `os.environ["OUTPUT_DIR"]`.

**Таблицы из PowerShell и Python.** Положите `*.csv` или `*.json` (массив объектов) в папку `$env:RESULT_DIR` —
после завершения они покажутся таблицами на вкладке «Результат».

Подробный формат манифеста и всех типов — в [спецификации](src/docs/spec.md).

## Где что хранится

- Настройки — `%APPDATA%\ScriptsManager\settings.json`.
- Недавние подключения — `%APPDATA%\ScriptsManager\connections.json`; пароли — в диспетчере учётных данных
  Windows.
- Рядом со скриптом в папке со скриптами: `.manifests\` — описания параметров (`Имя.sql.yaml`) и подробные
  описания (`Имя.sql.md`), `.presets\` — пресеты,
  `.output\` — вывод скриптов.
